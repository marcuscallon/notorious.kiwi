## Portfolio Operating Model

Marcus's working model is to build a portfolio of profitable lifestyle businesses, one at a time, rather than betting on a single venture. This is the operational path to his diversified-income goal.

- **Threshold — "established":** ~$5k gross margin per week, steady-state. At this point a venture has moved into operational and sustainable scale: it can keep building out, but Marcus caps effort at ~1 day/week on it so capacity shifts to the next venture.
- **Rhythm — steady-state:** ~1 day/week per established venture. Max 4 businesses running simultaneously → 4 days/week on steady-state, ~1 day/week for new-venture launch + portfolio overhead. (Math check: 4 × $5k/wk ≈ $20k/wk ≈ $1M annual GM at full portfolio — consistent with the original lifestyle target, reshaped as a portfolio rather than a single business.)
- **Launch phase:** The 1-day/week figure is aspirational steady-state only. Launch/scale runs higher (up to available hours: ~20 hrs/week pre-Sep 2026, ~40 hrs/week from ~Sep 2026), focused on ONE venture until it crosses the $5k GM/week threshold, then tapered.
- **Exits — mixed, decided per venture:** Some ventures built to sell (must be systematisable: ops docs, clean financials, no key-person risk); some retained with an operator running day-to-day; some harvested for cash flow then wound down. Exit shape is a venture-level decision, not a portfolio-wide rule — but the optionality means: build with *transferability in mind where cheap*, don't over-engineer it.
- **Distribution stance:** Each venture evaluated independently. Sales and cold conversations remain a drain (see What Drains You), but Marcus is open to AI-assisted GTM, account-based marketing, and other non-cold-outreach paths to market depending on the venture. The distribution-feasibility gate still applies per venture; the portfolio context is noted but not given special weighting.

**Implication for the co-founder:** When scoping any single venture, treat it as one of up to 4 portfolio slots, not the whole game. This argues for ruthless MVP scope, build-to-systematise where cheap, and an early per-venture view on which exit shape this venture is likely to take (sell / operator / harvest) so scope and documentation choices follow.
